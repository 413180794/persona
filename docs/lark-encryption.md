# 飞书加密消息迁移（#689）

## 已接入：读取展示

lark-connector 的 Agent 接口保留旧 `parts` / `textPreview`，新增版本化的 `olk` 展示投影。Hub 转发此字段，改写其中的媒体 URL；iOS 在成功解密时区分正文、对外展示和群密钥分发提示。无法解密时显示公开内容，并标注「加密消息 · 对外展示」；缓存未重新校验时标注「加密消息 · 仅显示公开内容」，不将外显误呈现为正文；普通文字即使含有「加密群密钥分发消息」也不会被误判为系统提示。

使用现有密钥库及 Agent 明文访问授权，不新增解密权限。授权中途撤销或账号变化时，上游不返回明文展示字段。未知或缺失协议版本不使用明文字段。缺失 / null 的公开内容统一视为空数组；单条可选加密投影不完整不阻断整页普通消息。图片仍沿用上游封面，本阶段不接加密图片的密钥或解密下载。

引用消息携带相同的展示信息；聊天引用与输入框引用在锁定、离线缓存、恢复草稿时均标明「对外展示」或「仅显示公开内容」，不会把外显当作被引用的原文。复制只取当前可见正文；加密消息不进入自动翻译。iOS 的消息和引用编码落盘时仅保留公开内容，清除旧文本字段、正文 parts 及结构化投影里的明文；重新打开后由服务器重新验证权限再读取。**此保护只覆盖 iOS 消息快照及引用草稿的编码路径**，不表示所有存储均已清除明文。收件箱的飞书来源和 Agent 上下文管线仍可能把旧 `textPreview` 压平后保存为正文（当时在 hub 的 lark*.go 和 lark_agent.go，#1571 起这两条链路都在接飞书的插件里，开源仓库的 server 代码不再读 `textPreview`）；其他消费方需要单独审计。此保护适用于带新投影的消息，无法从旧服务器已经压平的普通文字反推出加密属性。

## 手机解锁与加密文字发送（#689）

仅从首页「消息」进入的聊天增加「普通消息 / 加密消息」选择。选择加密后，再选一段历史内容作为对外展示；候选与 lark-connector 网页相同（两周前一天内的历史文字）。没有候选时保留草稿，不偷偷换成固定占位。首次发送遇到密钥库锁定，手机输入密码解锁；已开启统一密码时使用 lark-connector 登录密码，否则使用密钥库密码。密码只在解锁请求中短暂传递，不进入草稿、发件箱、日志或配置。

收件箱仍使用原输入区。两处共用同一个草稿和发件箱；若从收件箱打开尚未发出的加密草稿，保留草稿并引导回「消息」，不会按普通文字发出。首版支持普通私聊/群聊里的文字及引用回复；加密附件、话题群和线程输入区继续留在后续范围。

### 部署与授权

需要同时升级支持原生加密接口的 lark-connector（nwverse/lark-connector#997）及 Persona Hub；仅安装新 App 不会启用此能力。部署状态需单独核验，不能用 App 已安装或 PR 已合入代替。

1. 在 lark-connector 网页创建密钥库；读取解密正文的 Agent 授权仍沿用网页现有设置，原生发送授权不会开启它。
2. 在 lark-connector 部署环境设置独立的 `lark-connector_NATIVE_OLK_TOKEN` 和 `lark-connector_NATIVE_OLK_ACCOUNT_ID`。凭据使用新生成的 43–128 位 base64url 字符，不能复用普通 Agent token；账号是实际飞书用户 ID，不是 lark-connector 的账号槽位编号。
3. 在接飞书插件的设置里把密钥 `native_olk_token` 设为同一个独立凭据（#1571 起 hub 不再读 `hub.json` 的 `lark.native_olk_token`，见 `docs/config.md`）；`lark.account` 仍选择已登录的 lark-connector 账号槽位。重启两侧服务使配置生效。不要把凭据放进 App、仓库、PR、助手环境或二维码。
4. 撤销时移除或轮换 lark-connector 的原生凭据并重启；旧 Hub 无法继续原生解锁、准备密文或提交新的加密发送。已经被上游接受的消息不受撤销影响。普通 Agent 访问及读取解密授权互相独立。

没有独立授权、账号已变化、旧版本没有接口、密码错误或加密失败，都明确失败并保留输入，不回退明文。首次创建、密码重置后恢复以及授权配置仍在网页/部署端完成；手机负责解锁和发送，不导出私钥。公网沿用 Hub TLS 要求。

### 版本不支持时

选择加密或打开历史外显前先读取原生加密状态，使用当前会话的 Hub 与账号，不比较版本字符串。Hub 在握手中声明 `lark_native_encryption`，客户端仍实际请求状态，以兼容已支持接口但尚未声明能力的版本。Hub 缺少接口时提示升级 Hub；Hub 已支持但 lark-connector 缺少接口时返回 `lark_lark-connector_upgrade_required`（426），提示升级 lark-connector；独立授权缺失仍是 `OLK_VAULT_NATIVE_NOT_AUTHORIZED`（403），不是版本错误。网络、登录和会话错误不冒充需要升级。

提示提供「重新检查」。选择加密的意图与原有输入继续保存，失败不清空草稿，也不会偷偷切回普通发送。正常发送依然重新检查账号与授权。历史候选、解锁、准备密文、提交密文的旧接口错误也统一转换为可读提示，避免恢复旧草稿或部署切换时再次出现 `not found`。

### 重试与本机存储

先由密钥库生成密文，再原子保存草稿清空与待发送记录，然后提交。每条密文有稳定 UUID；一个逻辑消息可能含先行的群密钥分发消息，最后一条使用原消息 UUID，前序 ID 从该 UUID 确定性派生。中断后重试使用相同密文和 ID，不重新加密，避免重复发出。发送边界再次校验账号，lark-connector 使用 `expectedSenderId` 抵御登录切换；收件箱普通发送没有改变。

包含加密草稿或加密待发送记录时，整份本机发件箱快照使用 AES-GCM 保存，密钥仅在设备钥匙串；钥匙串暂不可读时不能覆盖旧快照。普通草稿继续兼容原格式。此处保护用户自己输入的待发送正文，不能据此宣称服务端所有消费路径都不保存明文（读取展示边界见上文）。加密发送只根据服务端消息 ID 或 client ID 合并回显，不靠正文相同或超时删除。
