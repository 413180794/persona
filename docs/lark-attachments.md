# 原生飞书图片与文件发送（#410）

现有 `LarkChatView` 输入框的「＋」选择照片或文件，先预览、移除，再发送。预览复用图片查看器（支持下拉关闭）与系统 Quick Look；消息继续使用原生飞书排版。

## 发送和确认

- 文本、图片、文件通过同一会话发送队列顺序提交；等待回显不会阻塞下一条提交。
- 每条消息有固定 client_id。文件选择后保存私有快照，重试不再读取可能变化或失去访问权限的原文件；启动时清理上次进程遗留的选取副本，后续 #713 的持久化媒体使用独立目录，不在清理范围。
- 请求成功保存 message_id；回显按 client_id / message_id 替换本机消息，附件不按空文本、文件名或超时删除。
- 失败保留附件，支持重发、放回输入框或删除；退出聊天再进入仍能恢复。队列按 Hub 凭据与会话隔离。
- 引用文字仍走主线回复接口，话题回复保持主线行为。文字与附件分别发送，附件暂不支持引用 / 话题回复。

## Hub 接口

专用 `images` / `files` 接口绑定 Hub 配置的 lark-connector 账号，复用设备认证与角色权限，不开放通用写代理。
图片校验编码大小与真实 MIME，文件流式上传并限制 Content-Length；保留 lark-connector 的登录失效错误码。老 Hub 提示先升级后发送附件。

## 限制与回归

每批最多 4 个附件。照片转换成 JPEG、最长边 2560 像素、清除位置元数据；原图和动图可选文件发送。文件 1 字节至 100 MiB。
文字和引用草稿沿用主线的持久化。尚未发送的附件草稿仅在当前页面保留；发件箱在进程内保留，离开页面后可继续核对已提交的附件。跨页面草稿及强退恢复由 #713 提供。

`LarkAttachmentTests` 覆盖快照隔离、大小边界、请求原始字节、重试幂等键、精确回显、引用路由与凭据隔离。
`LarkAttachmentFlowTests` 和 `LarkSendTests` 使用本地 mock Hub 验证预览、下拉关闭、失败退出重进、重试、普通文字、引用和话题回复。
截图见 [回归记录](screenshots/lark-attachments/README.md)。真实账号仅只读检查，不发送测试消息。

上传总时限按文件大小估算（128 KiB/s 加一分钟处理时间，至少三分钟，100 MiB 约十四分钟），手机与 Hub 使用相同预算；用户取消会立即向上游传递取消。lark-connector 的 pending / failed 本地副本不显示为已发送消息。
