# 国际化（i18n）

Apple（iOS / macOS / 手表 / 扩展）、安卓、网页和 hub 共用这一份约定。各端的实现可以不同，但语言列表、回退规则、术语和协议必须一致；有冲突以本文为准，要改先改本文。

## 支持的语言

| 代码 | 名称（选项里一律写这个，不随界面语言变） | 说明 |
| --- | --- | --- |
| `zh-Hans` | 简体中文 | 源语言：现有界面的文案，新文案先写中文 |
| `en` | English | 回退语言 |
| `ja` | 日本語 | |

代码只有这三个值，客户端发给 hub、存进设置、写进词条文件名都用它们，不带地区（不写 `zh-CN`、`en-US`、`zh_Hans`）。

## 选哪种语言

设置里的「语言」（iOS / Mac：设置 › 外观；安卓、网页放在同样的位置）有四个选项：**跟随系统**（默认）、简体中文、English、日本語。
选了具体语言就用它；跟随系统时按系统的**第一首选语言**解析（不往后找第二个）：

| 系统第一首选语言 | 结果 |
| --- | --- |
| 任何中文：`zh`、`zh-Hans`、`zh-CN`、`zh-SG`、`zh-Hant`、`zh-TW`、`zh-HK`、`zh-MO`… | `zh-Hans` |
| 任何日文：`ja`、`ja-JP`… | `ja` |
| 其他（`en-GB`、`fr`、`ko`、`de`…）或读不到 | `en` |

按语言子标签（第一段，大小写不敏感，`_` 当 `-`）判断，所以繁体也落到简体中文。各端自己写这个解析函数并做单元测试，**不要依赖系统的自动匹配**：
iOS 的 Bundle 匹配、安卓的资源限定符遇到没有的语言会落到开发语言（中文）或按自己的规则挑，和上表不一致。

- 某个词条在目标语言里缺失时：先用 `en`，再用 `zh-Hans`，都没有显示 key（只在开发版里出现，测试应该拦下来）。
- 切换语言立即生效，不需要重启（做不到即时的平台，至少要在设置页提示并在下次启动生效，不能静默不变）。
- 「Persona」和用户起的形象名字永远不翻译。

## 日期、数字、排序

一律用平台的格式化 API（`Intl.*`、`Date.FormatStyle` / `DateFormatter`、`java.text` / `DateTimeFormatter`），不手拼「月」「日」「周」，不写死 `zh_CN`。
格式化用的 locale：系统 locale 的语言和当前界面语言一致时用系统 locale（保留地区习惯，如 `en-GB` 的日期顺序）；不一致时用界面语言的代码（`zh-Hans`、`en`、`ja`）。
相对时间（「3 分钟前」）用 `Intl.RelativeTimeFormat` / `RelativeDateTimeFormatter`；复数用平台的复数规则（英文区分 one / other，中日只有 other）。

## 文案风格

- **中文**：保持现在的写法（中文和英文、数字之间留空格，「」做引号）。
- **English**：口语、简短，按各平台习惯写大小写：iOS / macOS 的导航标题、按钮用 Title Case（Apple HIG），安卓和网页一律 Sentence case（Material）。
  不逐字直译中文：「完成未看」写 Unread，不写 Completed not viewed；按钮是动词（Approve、Send），空状态一句话说清楚下一步。
- **日本語**：句子用です・ます体，按钮、标签用体言止め（「承認」「送信」「設定を開く」）；全角标点「、」「。」，引号用「」；
  日文和英文、数字之间**不加空格**（跟 Apple / Microsoft 的日文界面一致）；片假名长音按 Microsoft 规范保留（コンピューター、サーバー）。
- 三种语言都要放得下：英文平均比中文长 1.5–2 倍、日文略长于中文。按钮单行的规矩（`CLAUDE.md`）对三种语言都成立，放不下就缩短文案或换图标，不能换行或截断。
- 占位符一律有名字（`{count}`、`{name}`），不同语言的语序自己排；不拼接半句（`"已发送给" + name` 这种要改成一个带占位符的整句）。

## 各端的机制

| 端 | 词条在哪 | 机制 |
| --- | --- | --- |
| Apple | String Catalog（`.xcstrings`），按 target 分 | 源语言 zh-Hans，补 en、ja；`String(localized:)` / `LocalizedStringKey`。界面语言由上面的解析函数决定，覆盖系统的 Bundle 匹配；扩展（小组件、实时活动、通知扩展）和手表读 App Group 里同一个选择。细节由 Apple 端写进 `docs/ios.md` |
| 安卓 | `res/values*/strings.xml` | `values/` 放英文（系统回退落到英文），`values-zh/`（覆盖简繁）、`values-ja/`；应用内选择在安卓 13+ 写系统的按应用语言（`LocaleManager`），更早的系统存在 App 里；每个 Activity 在 `attachBaseContext` 按上面的解析函数固定资源的语言（App 是 `ComponentActivity`，没引入 AppCompat）。细节由安卓端写进 `docs/android.md` |
| 网页 | `web/src/i18n/locales/<语言>/<命名空间>.json` | 自写的小 `t()`（不加依赖）；key 是 `命名空间.名字`，占位符 `{name}`，复数用后缀 `_one` / `_other`（`Intl.PluralRules`）；日期、数字一律 `Intl`。见 `docs/web.md`「国际化」 |
| hub | `server/internal/i18n/locales/<语言>.json` | `i18n.T(lang, key, args)`，格式同网页；词条文件 `embed` 进二进制。给人看的文字（推送、任务通知、injected 消息、状态和错误文案、网页的服务端页面）按用户语言出；日志、CLI 输出、给 Agent 看的内部提示不翻译 |
| 提示词 | `server/internal/prompts/` | 提示词本身仍是中文写的一份，不按语言复制；要求「用某种语言回答」的地方换成模板变量（`{{.Language}}`，值是该语言的自称，如「简体中文」「English」「日本語」） |

三端都要有检查：三种语言的 key 一致、占位符一致，代码里不写死给人看的中文（测试数据、注释除外）。

## 协议：怎么把语言告诉 hub

hub 需要知道两种语言：**这次请求 / 这条连接**的（同步返回的错误、状态文案），和**这个用户**的（异步产生的东西：推送、助手的回答、injected 消息、机器人回复）。
客户端只发解析后的代码（`zh-Hans` / `en` / `ja`），不发「跟随系统」；用户改了语言或系统语言变了（跟随系统时），立刻按下面三处重新发一遍。

| 在哪 | 字段 | 作用 |
| --- | --- | --- |
| 每个 HTTP 请求 | 请求头 `Accept-Language: <代码>` | 这次响应里给人看的文字（`error`、状态说明、网页的服务端页面）。浏览器自带的 `Accept-Language`（`en-US,en;q=0.9`）也认，按上面的回退规则取第一项 |
| WebSocket | `client_hello.locale` | 这条连接上的 `notify`、`error` 等文案；同时更新用户语言（见下）。浏览器的 WebSocket 不能带请求头，所以靠这一条 |
| 设备登记 | `POST /api/v1/devices` 的 `locale` | 推给这台设备的通知用这种语言；没带时用用户语言 |

**用户语言**：hub 存在 Postgres `settings`（`user_locale`），取最近一次 `full` 角色的客户端在 `client_hello` 里报的 `locale`（手表、链路、互联凭据报的不算）。
助手回答、injected 消息、任务通知、飞书 / 微信机器人的回复、没有自己 `locale` 的设备的推送都用它。从来没有客户端报过时是 `zh-Hans`，所以旧客户端和现在的用户行为不变。
同一个人的几台设备语言不同时以最近声明的为准，这是有意的简化。

hub 支持这套协议时 `hello.features` 带 `locale`，`hello` 另带 `locale`（当前的用户语言）。旧 hub 忽略这些字段，客户端照常显示自己的文案。
插件 UI 上下文里已有的 `locale`（`zh-Hans-CN` 这种带地区的 BCP 47，[plugins.md](plugins.md)）保持原格式，语言部分取界面语言。
字段的细节以 [protocol.md](protocol.md) 为准。

## 后续工作（这一轮不做）

- **扩展清单的 l10n**：插件、连接器清单（`persona-plugin.json`）里的名字、描述、配置表单的标签目前只有一种语言。以后清单可以带 `l10n: {"en": {...}, "ja": {...}}`，hub 按请求语言选。
- 知识库里沉淀的内容（会话摘要、人 / 群 / 项目页）保持原来的语言，不跟着界面语言重写。
- 官网 `site/` 和隐私政策、服务条款。
- personad / Persona Link 的命令行输出和日志。
